Close the workflow-enforcement gaps

issue #25 branch chore/workflow-enforcement-gaps drafted 2026-08-27 in progress

01Status

in progress — design approved, implementing. Flips to approved before the PR ships.

02Problem

The three workflow skills already create an HTML design note per issue, but three gaps let process slip through unnoticed:

  • design-notes/ has no index — notes accumulate with nothing tying them to their issue or PR.
  • The explain-diff-gfm render writes its HTML to /tmp; only the GFM comment survives. The rich local-review artifact is never archived and nobody is told to open it.
  • Nothing forces a human to actually look at that explain-diff before merging.
  • ship-it runs /ponytail-audit but never a module-depth architecture pass.

03The change

Six edits — four to markdown skill files plus one new index file, two to CI workflow YAML. Nothing here has a runtime seam; the YAML is checked by reasoning and a lint, not a unit test.

  1. Add design-notes/README.md — an index table (issue, slug, status, PR). fix-it step 3 and feature-it step 4 gain two sub-steps: append a row when the note is created, and xdg-open the note (guarded) so it always opens in the browser on first draft. The approved flip re-opens it.
  2. Design notes are now hand-authored via /artifact-design as standalone self-contained HTML files (still committed, still shipped in the PR diff) instead of the explain-diff-gfm render template. This note is the first one built the new way.
  3. fix-it step 9 / feature-it step 10: render the explain-diff HTML with render.py -o design-notes/issue-<n>-explain-diff.html so it is committed in the PR diff, then xdg-open it (guarded for headless shells). The explain-diff keeps render.py — it needs the GFM twin for the PR comment.
  4. fix-it step 10 / feature-it step 11 merge gate: add “confirm the explain-diff HTML was reviewed” before gh pr merge.
  5. ship-it: new [HUMAN] step after /ponytail-audit — run /improve-codebase-architecture (it is disable-model-invocation: true, so the human runs it). Accepted deepening becomes its own branch/PR, then re-run.
  6. .github/workflows/release.yml and shared-publish-release.yml: add draft: true unconditionally to the action-gh-release step. Every release — this repo’s and every consumer card’s, since the second file is workflow_call — lands as an unpublished draft; a human publishes it from the Releases UI. The prerelease: line stays.

04Decisions

  • One PR. Folded into the existing uncommitted chore/workflow-enforcement-gaps branch work (the skill split itself, the pre-commit branch guard, tdd-guard wiring). Issue #25 is the umbrella.
  • Design notes keep living in the repo. /artifact-design informs the craft; the output is still a committed file, not a claude.ai Artifact — it has to ship in the PR diff.
  • Both HTML files stay committed per issue — the design note and the explain-diff. The directory grows over time; the index keeps it navigable.
  • xdg-open is guarded — 2>/dev/null || true so headless / SSH / CI runs never fail on a missing opener.
  • The ship-it architecture step blocks. The release flow stops for the human to run the pass — not downgraded to a non-blocking suggestion.
  • Every release is a draft — always. Never a bare publish, never plain pre-release. Draft is the strongest gate: nothing reaches the public without a human clicking Publish. Applied to the shared workflow_call file too, so it holds for every consumer card. That is a minor semver bump on the toolchain.

05Non-goals

  • No change to CLAUDE-SHARED.md — already lean after the branch’s earlier edit.
  • No change to explain-diff-gfm/scripts/render.py — it already takes -o; auto-open is a line in the calling skills, not a script flag.
