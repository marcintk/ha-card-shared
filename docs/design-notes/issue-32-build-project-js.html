Design note · ha-card-shared

Name the bundle after the card, not card.js

issue #32 branch feat/build-project-js drafted 2026-08-28 target v2.0.0 approved

01Status

approved — shipped as designed. The seam landed in one red–green slice; 113 tests pass at 100% coverage, and the smoke fixture now emits fixtures/smoke/dist/smoke.js, proving the rename end to end.

Two deviations from the plan, both discovered by the gates:

  • Added rollup.base.d.mts. The plan called the root-level test “free” because coverage include is src/** — true for coverage, but tsc rejected the test with TS7016, since rollup.base.mjs is untyped JS imported under strict. A declaration file beats a suppression comment here: rollup.base.mjs is an exported entry point, so consumers get the types too. Added to package.json files.
  • Fixed stale paths in the recipe. recipe.1.4.1_2.0.0.md still pointed at scripts/setup-claude.js and node_modules/ha-card-shared/hooks/…, both moved under harness/ in #31. Out of this issue’s scope strictly, but it is the file consumers execute, and it was being renamed anyway.

02Problem

cardBundle() in rollup.base.mjs hardcodes output.file: "dist/card.js". Every consumer card ships a file called card.js. It works — HACS installs each card into a folder named after its repo — but once a user has a few cards registered, every Lovelace resource URL ends in the same generic card.js and none of them is recognisable.

today/hacsfiles/ha-teamtracker-scoreboard-card/card.js
after/hacsfiles/ha-teamtracker-scoreboard-card/ha-teamtracker-scoreboard-card.js

cardBundle() already takes a name option that defaults to process.env.npm_package_name — it just isn't used for the filename.

03The change

One PR. The runtime seam is a single line in rollup.base.mjs; everything else is workflow YAML, docs, and the migration recipe — verified by reasoning and lint, not unit tests.

  1. rollup.base.mjs — output.file becomes `dist/${name || "card"}.js`. The "card" fallback keeps today's behaviour when npm metadata is absent (rollup invoked outside npm run). The banner's use of name is left untouched.
  2. test/rollup-base.test.ts (new) — the one red–green slice. Two cases: an explicit name yields dist/<name>.js; with npm_package_name stubbed undefined, cardBundle() falls back to dist/card.js. Coverage include is src/**, so a root-level test is free.
  3. .github/workflows/shared-publish-release.yml — a new step derives the name from package.json (node -p "require('./package.json').name") into a step output; the release upload becomes files: dist/${{ steps.name.outputs.name }}.js. An explicit name fails the release if the build emitted the wrong file rather than globbing whatever is in dist/.
  4. .github/workflows/shared-deploy-demo-page.yml — derive $NAME the same way and copy dist/$NAME.js → _site/$NAME.js. The demo page is renamed end-to-end; consumers update their docs/index.html import as part of pickup.
  5. Docs — CLAUDE-SHARED.md (lines 3, 9), README.md (line 44), and harness/skills/ship-it/SKILL.md (line 53) all change dist/card.js to dist/<project>.js, noting the name comes from package.json with a card.js fallback.
  6. Version & recipe — package.json drops 2.0.1 → 2.0.0 (neither was ever tagged; last published release is v1.4.1). recipes/recipe.1.4.1_2.0.1.md is renamed to recipe.1.4.1_2.0.0.md with 2.0.1 → 2.0.0 through its body; recipes/dependabot.md updates the link and adds an asset-rename line under ### v2.0.0. The migration section below is folded into that same recipe.

04Migration — consumer pickup

The shared PR is self-contained. The four consumer cards (ha-news-card, ha-planetary-solar-system-card, ha-teamtracker-scoreboard-card, ha-yahoofinance-board-card) all pin ha-card-shared#v1.4.1 — nothing changes for them until they bump. On pickup, each runs this checklist (folded into recipe.1.4.1_2.0.0.md):

  1. Bump the pin + workflow refs to v2.0.0, npm install, rebuild.
  2. hacs.json — "filename": "<repo>.js".
  3. README.md — manual-install download name and the /local/<repo>/<repo>.js URL.
  4. docs/index.html — import "./<repo>.js".
  5. planetary only — the demo recorder rig (scripts/demo/record-demo.mjs and .json, record-harness.html) references docs/<repo>.js.
  6. End users re-point the Lovelace resource URL from …/card.js to …/<repo>.js — a 404 until they do.

Load-bearing: step 2. HACS reads hacs.json's filename to choose which release asset to install. Ship a 2.0.0 release without updating it and HACS installs break for that card's users. It goes first in the recipe and in the release notes' “what you'll notice” section.

05Decisions

  • "card" fallback, not a loud failure. A missing package name is a misconfiguration the bundle can't fix anyway; falling back preserves today's exact behaviour when npm metadata is absent.
  • Explicit name step in the release workflow, not a dist/*.js glob. The release asset is the artifact that matters most — a wrong filename should fail the release, not ship a mystery file.
  • Demo page renamed end-to-end. Consistent with the release asset; the per-consumer docs/index.html edit rides in the recipe.
  • One PR. The version drop and recipe rename exist because this change needs a correctly-named recipe to write into, and 2.0.0 is unreleased — no history to protect. Splitting would stack a PR for ~4 trivial line edits.
  • Target v2.0.0. 2.0.1 and the never-published 2.0.0 collapse into one major jump from v1.4.1; the asset rename is itself a breaking change for consumers, so major fits.

06Non-goals

  • Editing the four consumer repos — that's their own pickup work, driven by the recipe.
  • Guarding the banner's use of name — its latent undefined predates this change and is out of scope.
  • Shipping both card.js and <project>.js for a transition period — over-engineering for a handful of known consumers.
