Design note · ha-card-shared

Union, not override: rewriting skill-guard as phase × role

issue #36 branch refactor/skill-guard-phase-role drafted 2026-08-29 approved

01Problem

Two audits back (the harness rebuild plan), skill-guard turned out to be two guards stapled together, and only one of them ever worked.

The skill layer was dead on arrival. A PreToolUse × Skill hook recorded the active skill into one slot; a Stop hook deleted it. Stop fires when Claude finishes responding — every turn boundary — so the recorded skill was gone by the first [HUMAN] gate in any multi-turn pipeline. It was never providing the protection its own policy file claimed.

The role layer worked, and had four real bugs. pipeline-reviewer's deny_write: ["."] matched every path, so /simplify could apply nothing — contradicting the role's own job. pipeline-coder deadlocked mid-slice: the moment its first edit turned the target test green, every further src/ write in that same slice was refused. The probe behind that (suiteGreen()) ran the whole test suite inside a 30s PreToolUse hook on every write — several full runs per slice, silently switched off past the timeout, any unrelated non-zero exit misread as “red”. And path matching (raw.startsWith(cwd)) failed selectively: a symlinked checkout or a double-slash working directory left the absolute path unstripped, so ^src/ silently stopped matching while a blanket ["."] rule kept working — the TDD guard could go dark without anything looking wrong.

02The shape: union, not override

The old design treated skill and role as alternatives — agent_type beats the recorded skill; whichever resolves, its rules apply alone. The new design replaces the dead skill layer with an explicit phase the entry-point skill sets itself (skill-guard.mjs phase design|code|ship|release, written to .claude/skill-guard/phase, expiring after 8h rather than 30 minutes — long enough to survive a real multi-turn design session), and resolves phase and role together: a call is denied if either denies it.

deny(call) = phase.denies(call) ∨ role.denies(call)

Concretely: phase code allows a commit, but if the active subagent is pipeline-explore (whose role always forbids commits), the call is still denied — the union means neither side can be a loophole for the other.

03The four fixes

Reviewer. deny_write becomes ["^test/", "\.test\.ts$"] — matches the role's own description (“read-only except for what /simplify applies”) instead of contradicting it.

Coder: a marker, not a probe. suiteGreen() is gone entirely. skill-guard.mjs red <test-file> writes a marker (also expiring, 30 minutes, so a forgotten marker can't leave the TDD gate open forever); pipeline-coder may write src/ only while it's present; skill-guard.mjs green clears it once the slice is accepted. Mechanical, and off the hook's latency path — no more subprocess test run inside a 30s PreToolUse budget.

Path normalization, done properly. realpathSync on both the guarded root and the target (tolerant of a target that doesn't exist yet — walks up to the nearest real ancestor, reattaches the rest), then path.relative. A target that resolves outside the project root is denied unconditionally under any guarded context, independent of whether any specific deny_write pattern happens to match — closing exactly the class of escape a pattern-only check would miss. Verified against this exact session's own working directory quirk: launched with an “Additional working directory” of /home/marcintk/Development/ha//ha-card-shared (double slash) alongside the primary path — both now resolve to the identical canonical root.

deny_bash, unanchored. Every pattern lost its ^\s* anchor, which by itself defeats cd x && git push, env FOO=bar git push, and a command wrapped in bash -c '...' or split across lines — an anchored pattern only ever looked at the very start of the string. One added normalization step strips git's -C <dir> / -c key=val global flags before matching, so git -C . commit reads as git commit. This is a guardrail, not a sandbox — the docs say so.

Visibility. Every check decision — allow or deny, phase, role, tool, reason — is appended to .claude/skill-guard/log. Fail-open stays the default on any read error, but for the first time there's a durable trail of what the guard actually did, not just what it was supposed to do.

04Guardrail

test/harness/skill-guard.test.ts — 23 new cases spawning the hook as a real subprocess with crafted payloads, matching every item the issue's acceptance criteria named: the union (phase-only deny, role-only deny, both-allow, a stale phase treated as none), reviewer's src/test split, the coder marker's full red→write→green→deny cycle, path escape under a role with no matching deny_write pattern, a symlinked cwd, a double-slashed cwd, all three deny_bash bypass patterns plus one confirming a legitimate command still passes, fail-open on invalid JSON and on SKILL_GUARD_OFF=1, and the decision log recording both an allow and a deny.

Two existing test files needed updating to assert the new, intentional shape rather than the old one: test/scripts/setup-claude.test.ts (the hook wiring is now a single check entry, no Skill matcher, no Stop hook — plus a new case proving an upgrading consumer's stale pre-3.0 hooks get stripped, not left dangling) and test/skills/claude-shared.test.ts (the policy names phases now, not skills).

05A test-harness mistake, kept in the log

Mid-verification, an initial smoke test called skill-guard.mjs phase code without piping a cwd, from the actual repo checkout. That's not a bug in the script — phase/red/green are meant to be run directly by a skill's own Bash step (no hook payload involved), so defaulting to process.cwd() is exactly correct — it just meant the test accidentally wrote a stray phase file into this repo's own .claude/skill-guard/ instead of the intended scratch directory. Caught, confirmed harmless (a later phase clear in the same broken test removed it), cleaned up, and the test redone by cd-ing into the scratch dir for those calls — matching how a real skill invokes them.

06Non-goals

Wiring any real skill to call skill-guard.mjs phase. No entry-point skill sets a phase yet — /design-it, /code-it, /ship-it, /release-it don't exist until #37. Until then the phase mechanism exists and is fully tested, but nothing in this repo actually invokes it; only the role layer (agent_type, already wired to the pipeline subagents) is live today.

Updating the v1.4.1→2.0.0 migration recipe. This change needs zero consumer action — postinstall migrates a stale hook automatically, proven by the new “strips a pre-3.0…” test — so there's nothing to add to the recipe yet. The recipe gets finalized once the full #33–#38 sequence is ready to ship as one release.
