01

What it does

One entry point for design, whatever the change — a bug fix, a feature, a chore, a one-line dependency bump. A trivial change still takes this path; it just moves fast. The skill prints each step as - [ ] before starting it and - [x] when done, and never skips one silently — if a step can't be honestly checked, it stops and asks.

skill acts [HUMAN] gate sub-agent approved
  1. step[ ]1

    Arm the guardrail

    skill

    node harness/hooks/skill-guard.mjs phase design — sets the active phase. From now on the hook denies writes to src/ and test/ and denies git commit / push / gh pr / npm version. Survives Stop; expires after 8 h.

    runsharness/hooks/skill-guard.mjs
  2. step[ ]2

    Read the issue

    human input

    gh issue view <n> --json title,body,comments. The issue is the entire input — nothing else is assumed.

    callsgh
  3. step[ ]3

    Grep the lessons log

    skill

    Search LESSONS.md for this problem class before thinking about an approach. Report any prior root cause and the guardrail already in place — a fix already guarded against is not this issue.

    readsLESSONS.md
  4. step[ ]4

    Reconnaissance

    sub-agent · explorer

    1–3 explorer agents in parallel when scope is uncertain: reproduce the bug with concrete evidence and state what's ruled out, or scan prior art and reusable patterns for a feature. Read-only — the hook blocks it from writing files or mutating git. Skipped for a genuinely trivial change.

    spawnsharness/agents/explorer.md
  5. step[ ]5

    The grill

    human · brainstorm-it

    Runs brainstorm-it as a sub-skill: one question at a time, each with a recommended answer, but the decisions are the human's. One concern per issue — anything extra becomes a separate GH issue, not scope creep.

    callsharness/skills/brainstorm-it
  6. step[ ]6

    Design it twice

    skill

    For anything non-trivial: 3+ parallel sub-agents each produce a radically different interface — minimal, maximally flexible, common-case-trivial, ports-and-adapters — compared on depth, locality, and seam placement before any is judged. A single-approach note cannot be finished. Works from design-methods/.

    readsdesign-methods/glossary.mddesign.mddiscipline.mdprocesses.md
  7. step[ ]7

    Adjacent-opportunity pass

    skill

    Before converging: what does this change make cheap, and what does it foreclose? Anything worth doing separately is named and filed as its own GH issue — never folded in here.

  8. step[ ]8

    Write the note

    skill · explain-it

    explain-it start <n> <slug> creates docs/design-notes/issue-<n>-<slug>.html at status in progress, adds the README row, and opens it in the browser. The slices this change breaks into are declared directly in the note.

    callsharness/skills/explain-it
  9. ↶ Step 9 — loop 5 – 8 until the human approves. Re-grill, re-design, re-slice. The skill deliberately does not settle on the first workable answer.
  10. step[x]10

    Approve

    done

    On the human's approval, explain-it approve <n> <slug> flips the status badge to approved. Output: one approved design note, ready for /code-it.

    callsharness/skills/explain-it
02

Two ways in

The steps above assume an issue number. When there isn't one, the skill either scans for a candidate and files it, or hands off to brainstorm-it to draft it first.

03

The shape of a run

Steps 1–8 execute inside the armed guardrail. Steps 5–8 are a loop, not a line — they repeat until the human approves. Step 6 fans out.

04

What it uses

The skill file is ~55 lines. Almost everything it does is delegation — to a hook, two sub-skills, one sub-agent, and a four-file reference.

Guardrail hook

harness/hooks/skill-guard.mjs
· skill-guard.json Phase/role-aware PreToolUse gate. Step 1 sets phase design; the policy then denies src/ + test/ writes and commit / push / pr / version. Every decision is logged; unreadable state fails open.

Sub-skills

harness/skills/brainstorm-it The step-5 grill. One question at a time, recommended answer each, decisions stay with the human. Also the pre-issue on-ramp that drafts an issue from a raw idea.
harness/skills/explain-it Single owner of docs/design-notes/ and LESSONS.md. start creates the note (step 8); approve flips the badge (step 10). Later phases — slice, compound, finalize — belong to /code-it and /ship-it.

Sub-agent

harness/agents/explorer.md Read-only reconnaissance for step 4 (and the no-arg scan). Traces the real code path, gathers concrete evidence, reports file:line pointers — proposes no fix. skill-guard blocks it from any write or mutating git.

Design-methods reference

design-methods/glossary.md The fixed vocabulary — module, interface, depth, seam, adapter, leverage, locality. Read every run; used verbatim in the note and in conversation.
design-methods/design.md How to shape an interface. Read on every non-trivial change (step 6).
design-methods/discipline.md The fast checks — deletion test, one-adapter-vs-two, replace-don't-layer, the red-flag list — run against each proposed design.
design-methods/processes.md The playbooks: scanning for candidates (no-arg mode), deepening a cluster, design it twice (step 6).

External

gh gh issue view for the input (step 2); gh issue create in no-arg mode and whenever an adjacent opportunity is split off.
LESSONS.md The by-symptom log, grepped at step 3 before any approach is considered.
05

How it addresses the task

The task is not "produce a plan" — it is "don't let the codebase accrete complexity one reasonable-looking commit at a time." Six design choices do that work.

a State is just the note and the issue

There is no hidden progress to lose. Re-invoking /design-it <n> on an existing note — from any conversation — reopens and re-grills it. The design survives the session that made it.

b It refuses to converge early

The grill, design-it-twice, and the adjacent-opportunity pass are where the "keep the design clean" budget is spent. Step 9 loops 5–8 until the human — not the skill — is satisfied. A single-approach note is declared unfinishable.

c Guardrails, not good intentions

Step 1 arms skill-guard so the phase cannot write src/ or test/ or commit anything. The explorer sub-agent is additionally read-only. A block means someone strayed out of scope.

d One issue, one concern

Extras surfaced during the grill or the adjacent pass become their own GH issues on the spot. Scope cannot creep because the skill files the creep as separate work.

e Fixed vocabulary

Every run reads glossary.md and uses its terms exactly — no "component", "service", "API", "boundary". Notes and grills stay comparable across changes and across time.

f Every step is visible

Each step is printed - [ ] then - [x]; a step that can't be honestly checked stops the run. Every [HUMAN] gate opens with what changed, why it matters, and the risk if wrong — not a status recap.
