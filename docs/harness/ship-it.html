01

What it does

Never runs ahead of /code-it — a branch with unreviewed or unaccepted slices means stop and point back at it, not ship anyway. Thirteen steps, one finalize commit on top of the slice commits, one PR, and exactly one [HUMAN] gate: "merge it". Same - [ ] / - [x] discipline as the rest of the pipeline.

02

The shape of a run

Setup and the record (1–2), the commit landing (3–4), the PR and its trail (5–8), one human pause (9), then merge and reset (10–13). Linear — the only backward edges are the two git hooks in steps 3–4.

03

The commit gauntlet

The message is written once. The commit and the push may bounce off either local git hook until both pass — and these hooks fire on the real git operation, whoever runs it, independent of skill-guard.

04

What it uses

One phase of the shared hook, the two local git hooks, two sub-skills, the explain-diff renderer, and gh for everything that touches GitHub.

Guardrail hook

harness/hooks/skill-guard.mjs
· skill-guard.json Phase ship allows git commit / push / gh pr create|merge but denies src/ + test/ writes and npm version. Step 13 clears the phase entirely.

Local git hooks — harness/.githooks/

pre-commit Blocks direct commits to main; runs npm run check (biome lint + format auto-fix over src/ test/ harness/) and format:md (prettier); re-stages only the originally-staged paths; then typecheck (+ typecheck:harness). set -e — first failure aborts.
pre-push Runs npm run test:coverage — the push is blocked unless the 100% threshold holds.

Sub-skills

harness/skills/commit-it Writes the Conventional Commits message and the two mandated trailers — message only. Does not stage, commit, amend or push; the caller does that and loops until pre-commit passes.
harness/skills/explain-it
· scripts/render.py finalize gathers the branch diff, writes a JSON spec (background / intuition / code sections + a five-question quiz), and renders issue-<n>-explain-diff.html and the GFM string. Fills the README Explain-diff link.

External

gh pr create (5), pr comment --body-file (7), issue body edit (8), run watch (10), pr merge --rebase --delete-branch (11).
git commit -F - (3), push -u origin HEAD (4), checkout main && pull (12).

Records it updates

docs/design-notes/README.md The issue's row — Explain-diff link at step 2, PR link at step 6.
the GH issue body Overwritten at step 8 with the final snapshot — what shipped, note link, PR link.
05

How it addresses the task

The task is to get the reviewed branch merged cleanly, with the record complete, and leave no pipeline state behind. Six choices do that work.

a It won't ship what isn't accepted

A branch with unreviewed or unaccepted slices stops the skill — it points back at /code-it rather than opening a PR for half-done work.

b The record ships with the code

The explain-diff HTML is in the PR diff; the GFM is a PR comment; the README row and the issue body are updated in the same run — before the merge, not "later".

c Two hooks the model can't talk past

pre-commit and pre-push fire on the real git operation. Formatting, types and 100% coverage are enforced at commit and push, not trusted to have been kept.

d Rebase-merge, delete branch

Each reviewed /code-it slice lands on main as its own commit, followed by the finalize commit — history mirrors the note's slices, and every commit on main passed review and the suite.

e One human gate, well briefed

Exactly one "merge it" pause. It opens with what changed, why it matters and the risk if wrong — a decision brief, not a status recap.

f The phase clears itself

Step 13 resets skill-guard, so a stale ship phase can't leak into the next change. The next /design-it starts from a clean guardrail.
